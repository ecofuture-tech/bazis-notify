# bazis-notify 0.1.0

The first release of stored user notifications for Bazis. It requires `bazis>=2.11.0`
and `bazis-users>=2.9.0`. Install the optional `ws` extra (`bazis-notify[ws]`) for live
delivery through `bazis-ws>=2.6.0`.

## What it does

- `bazis.contrib.notify.service.notify()` stores one immutable `Notification` per
  recipient, rendering the title and body in that user's language. `notify_all()` sends
  to a queryset or iterable in batches, and `dedupe_key` makes retries idempotent.
- Apps register notification types in `<app>/notifications.py` with
  `bazis.contrib.notify.registry.register()`.
- `bazis.contrib.notify.router` exposes the authenticated user's inbox: list and retrieve,
  mark read or unread, delete, `unread_count`, `read_all`, and `clear`.
- With `bazis-ws`, new notifications and read/delete changes are published after the
  current transaction commits. With `email=True`, messages are sent after the commit
  through Bazis' default mail backend.
- `delete_expired()` removes old rows in batches for a periodic cleanup task.

## Settings

- `BS_BAZIS_NOTIFY_RETENTION_DAYS` controls retention. It must be a positive integer;
  the default is empty, which keeps notifications forever. The setting is consumed by
  `delete_expired()` and does not delete anything automatically.
- E-mail delivery uses the core mail settings (`BS_BAZIS_EMAIL_*` / `BAZIS_EMAIL_*` and
  `DEFAULT_FROM_EMAIL`), not package-specific credentials.

## Limitations and compatibility

- Notifications are created by `notify()` or `notify_all()`, not through the API. The API
  only exposes the current user's notifications; requests without a valid token receive
  401, and another user's notification is not accessible.
- A notification cannot be edited except for `read_at`. Metadata is sanitized for keys that
  look like secrets before it is stored or published.
- Delivery is best effort after commit: Redis or mail failures are logged and do not roll
  back the stored row. Without `bazis-ws`, notifications remain stored (and can still be
  e-mailed) but are not delivered live.
- Retention deletes both read and unread notifications. Run `delete_expired()` from a
  scheduled task when automatic cleanup is required.
